### What the demo covers

```text
                         PRIVATE S3 BUCKET
                                │
                 Block Public Access = ON
                                │
                 ┌──────────────┴──────────────┐
                 │                             │
          private/report.txt             uploads/*
                 │                             │
                 │ GET                         │ PUT
                 ▼                             ▼
          Presigned GET                  Presigned PUT
                 ▲                             ▲
                 │                             │
                 └──────── Python App ─────────┘
                                │

```

The Python application gets only:

```text
s3:GetObject  → private/*
s3:PutObject  → uploads/*
```

It does **not** get `ListBucket`, `DeleteObject`, bucket administration, or public-access permissions.

AWS confirms that the principal generating the presigned URL must itself have permission for the underlying S3 operation. ([AWS Documentation][1])

# 6. Python — Generate GET URL

`app/presign_get.py`

```python
import argparse
import boto3

from config import get_config


def generate_download_url(key: str, expires_in: int = 300) -> str:
    region, bucket = get_config()

    s3 = boto3.client(
        "s3",
        region_name=region,
    )

    return s3.generate_presigned_url(
        ClientMethod="get_object",
        Params={
            "Bucket": bucket,
            "Key": key,
        },
        ExpiresIn=expires_in,
    )


if __name__ == "__main__":
    parser = argparse.ArgumentParser()

    parser.add_argument(
        "key",
        help="S3 object key, e.g. private/report.txt",
    )

    parser.add_argument(
        "--expires-in",
        type=int,
        default=300,
        help="URL lifetime in seconds",
    )

    args = parser.parse_args()

    url = generate_download_url(
        args.key,
        args.expires_in,
    )

    print(url)
```

Boto3's `generate_presigned_url()` takes the S3 client operation, parameters, expiration, and optionally HTTP method. ([AWS Documentation][2])

# 14. Now implement upload

`app/presign_put.py`

```python
import argparse
import boto3

from config import get_config


def generate_upload_url(
    key: str,
    content_type: str,
    expires_in: int = 300,
) -> str:

    region, bucket = get_config()

    s3 = boto3.client(
        "s3",
        region_name=region,
    )

    return s3.generate_presigned_url(
        ClientMethod="put_object",
        Params={
            "Bucket": bucket,
            "Key": key,
            "ContentType": content_type,
        },
        ExpiresIn=expires_in,
        HttpMethod="PUT",
    )


if __name__ == "__main__":

    parser = argparse.ArgumentParser()

    parser.add_argument(
        "key",
        help="S3 destination key",
    )

    parser.add_argument(
        "content_type",
        help="Content-Type",
    )

    parser.add_argument(
        "--expires-in",
        type=int,
        default=300,
    )

    args = parser.parse_args()

    url = generate_upload_url(
        args.key,
        args.content_type,
        args.expires_in,
    )

    print(url)
```

AWS supports presigned URLs for uploads as well, and the uploader does not need AWS credentials; the URL is limited by the permissions of the principal that created it. ([AWS Documentation][4])

# 18. Why the application should NOT accept arbitrary keys

This is extremely important.

Don't build:

```text
GET /presign?key=<anything>
```

without authorization.

Imagine a user sends:

```text
GET /presign?key=private/admin-passwords.txt
```

If your backend blindly generates the URL, you've created a security vulnerability.

Instead:

```text
User
 │
 ▼
Application
 │
 ├── Authenticate user
 │
 ├── Determine resource owner
 │
 ├── Authorize access
 │
 └── Generate URL
         │
         ▼
        S3
```

For example:

```python
if not user_can_access(user, document):
    return {"error": "Forbidden"}, 403
```

Then:

```python
key = document.s3_key
```

rather than trusting the user-provided S3 key.

# 19. Why the PUT prefix is also restricted

Our policy says:

```json
{
  "Effect": "Allow",
  "Action": "s3:PutObject",
  "Resource": "arn:aws:s3:::YOUR_BUCKET/uploads/*"
}
```

Therefore the application can generate an upload URL for:

```text
uploads/image.jpg
```

but not:

```text
private/report.txt
```

That's intentional.

```text
                    IAM
                     │
          ┌──────────┴──────────┐
          │                     │
     GetObject               PutObject
          │                     │
          ▼                     ▼
      private/*             uploads/*
```

This is much better than:

```json
{
  "Effect": "Allow",
  "Action": "s3:*",
  "Resource": "*"
}
```

# 20. One subtle security point about expiry

Our demo uses:

```python
ExpiresIn=300
```

which is:

```text
5 minutes
```

AWS states that SDK/CLI-generated presigned URLs can be configured up to 7 days, but the actual lifetime is also constrained by the credentials used to generate them. Temporary credentials cannot create a URL that outlives those credentials. ([AWS Documentation][1])

So:

```text
ExpiresIn = 3600
```

doesn't magically mean:

> "The URL is guaranteed to work for one hour."

If the underlying temporary credentials expire earlier, the URL stops working earlier.

# 21. What happens internally?

Suppose Python generates:

```text
GET
private/report.txt
ExpiresIn=300
```

AWS SDK signs the request using the application's AWS credentials.

The URL contains parameters such as:

```text
X-Amz-Algorithm
X-Amz-Credential
X-Amz-Date
X-Amz-Expires
X-Amz-SignedHeaders
X-Amz-Signature
```

The client doesn't need to understand any of this.

It simply does:

```http
GET https://bucket.s3.ap-south-1.amazonaws.com/private/report.txt?...signature...
```

S3 validates the signature and request parameters.

```text
Client
  │
  │ HTTPS GET
  ▼
S3
  │
  ├── Signature valid?       ✓
  ├── Not expired?           ✓
  ├── Correct bucket/key?    ✓
  ├── Correct operation?     ✓
  └── Signing principal
      authorized?            ✓
             │
             ▼
          Object
```

If validation fails:

```text
403 Forbidden
```

AWS also notes that signed request parameters/headers must match what was signed; mismatches can produce `SignatureDoesNotMatch`. ([AWS Documentation][1])

## 24. GET vs PUT summary

|                               | Presigned GET              | Presigned PUT |
| ----------------------------- | -------------------------- | ------------- |
| Purpose                       | Download                   | Upload        |
| S3 operation                  | `GetObject`                | `PutObject`   |
| Client needs AWS credentials? | ❌                          | ❌             |
| Bucket needs to be public?    | ❌                          | ❌             |
| File travels through backend? | ❌                          | ❌             |
| Typical use                   | Documents, reports, images | User uploads  |

### One important improvement for your actual production implementation

The ZIP's policy uses:

```text
private/*
uploads/*
```

because this is a **learning/demo repository**.

For production, I'd tighten it further:

```text
arn:aws:s3:::bucket/private/${tenant-id}/*
arn:aws:s3:::bucket/uploads/${tenant-id}/*
```

and have the application derive the tenant/user prefix from the authenticated identity rather than accepting it from the request.

That is the difference between a **working presigned URL demo** and a **production-grade least-privilege design**.
